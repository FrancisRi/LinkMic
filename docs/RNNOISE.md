# Windows 0.3.2+：RNNoise 背景降噪

在电脑端“连接与音频”页面的“输入音量”卡片中，勾选 **RNNoise 背景降噪** 即可启用。连接前和连接中均可切换，关闭后恢复接收到的原始声音，不需要断开重连。
首次使用默认关闭；开关偏好保存到当前 Windows 用户的 `%LOCALAPPDATA%\LinkMic\audio-settings.json`，下次打开自动恢复。

## 更新

关闭旧客户端，完整解压当前的 `LinkMic-Windows-0.3.3-win-x64.zip` 后运行 `LinkMic.exe`。
程序旁边的 `rnnoise.dll` 是必要的降噪组件，请保留在同一目录。
手机当前版本为 Android 0.2.3，已有配对和 VB-CABLE 驱动继续使用，无需重新安装或配对。

库缺失或无法加载时，界面会禁用降噪选项并提示使用完整更新包，应用仍可启动。
处理初始化/数据错误时关闭降噪、显示提示并继续原始音频传输。
处理开关不会改变蓝牙/Wi-Fi 连接、会话计时或静音行为。

## 处理方式

采用 Xiph 官方 RNNoise **v0.2**，源码固定到 `904a876dce1f9ab8860c0a5000ed151f9f6eef58`，
嵌入该版本指定的默认模型 `0b50c45`，在本机离线运行。来源、源码/模型归档 SHA-256 和编译信息保存在 `third-party/rnnoise/provenance.json`；发布包中保留许可和来源记录。

链路为：手机音频 → 原有解码/缓冲 → RNNoise（可选）→ 原有增益/静音 → 音频输出/VB-CABLE。
48kHz 单声道的每个 20ms 数据块拆为两个 480 采样点的 10ms 块。
RNNoise 浮点接口使用 int16 幅度范围；关闭时不转换、不延迟、不改写输入 PCM。
上下文和缓冲由音频工作线程持有，界面只更新开关标志，避免在 UI 线程处理音频或并发销毁 native 状态。
关闭、会话结束时释放处理状态，重新开启时使用新状态，避免残留上一段音频。
开关按 20ms 音频块边界生效；启用时存在算法延迟，未新增传输队列。

这次仅接入电脑 RNNoise。安卓原有系统降噪/AEC 保持原样，系统实现可能与电脑降噪叠加；
具体音色、轻声与尾音保留效果需用原手机实听，必要时可随时关闭电脑降噪。

## 构建与验证

- `scripts/build-rnnoise.ps1` 使用工作区已有 MSVC/Windows SDK 编译，无需安装全局编译环境。
- Windows x64 SSE2 基线；静态 CRT，DLL 仅依赖 KERNEL32，无需额外 VC 运行库、GPU 或网络服务。
- 保持上游算法/模型源码不变，仅通过编译宏选择 SSE2 路径。上游浮点常量的 C4244/C4305 转换警告在 vendor 构建中单独豁免，其他 native 警告作为错误。
- `scripts/verify-windows.ps1` 包含 `--rnnoise-check`：真实 native 噪声处理、关闭时 PCM 精确相同、50 次开关、独立会话/重置、设置保存/恢复，以及真实 WPF 开关与生产 Receiver 的回环传输、静音和断开。
- 另保留原有输出、配对存储、主题、会话断开和蓝牙库释放回归。测试不打开物理音频输出，也不修改真实用户的降噪偏好。

本机合成噪声测试每 20ms 块的处理 P95 约 0.93ms（一次本地测量；重复运行会变化）。
这不是完整应用 CPU 占用率、端到端延迟或真实人声质量保证。
白噪声的 RMS 衰减只用于证明库确实工作，不代表实际语音信噪比或所有噪声的抑制程度。
本轮未启动 ADB、安装驱动或进行手机/蓝牙实机听音。

证据：`artifacts/tests/rnnoise-results.json`、`rnnoise-light.png`、`rnnoise-dark.png`，以及发布核验文件。
