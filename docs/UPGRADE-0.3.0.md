# Windows 0.3.0 / Android 0.2.0

本版处理两小时实机测试后的三项优化：连接时长、首次配对后记住设备，以及 Android Material 3 界面。

## 更新和使用

1. 关闭旧版电脑客户端，解压 `LinkMic-Windows-0.3.0-win-x64.zip` 并运行新版。现有 VB-CABLE 驱动继续使用，无需重装。
2. 在手机安装 `LinkMic-Android-0.2.0-debug.apk`。包名不变，签名校验见验证记录；保留本机 debug 签名时可覆盖安装，建议直接更新，避免卸载清除设置。
3. **升级后首次连接输入一次电脑上显示的六位配对码。**旧版未建立持久设备凭据，因此需要这一次新的配对。
4. 后续仍按原来的顺序点击两端开始连接，手机无需再填码。重启应用、重启设备，或在同一对设备之间切换蓝牙和 Wi-Fi，均使用已保存的设备身份。

必须更新手机和电脑两端，才能使用免码重连。旧 Android 0.1.0 仍可用原协议连接新电脑端，但不会获得设备记忆；新 Android 0.2.0 需要 Windows 0.3.0 或更高版本。

首次连接另一台电脑需要为那台电脑单独配对。IP 地址变化不会清除设备身份，但 Wi-Fi 仍需填写当前电脑的正确地址。
设备记忆不等于自动启动或自动录音：只有用户开始连接、身份校验通过后才启动录音，断开后释放麦克风。

## 界面和计时

- 手机和电脑均移除不断增长的帧数显示，改为 `HH:mm:ss` 本次连接时长；超过 24 小时继续累计小时数。
- 计时从身份验证成功开始，使用单调时钟，不受系统时间校准影响；手机退到后台、再打开或旋转屏幕时仍显示同一次会话的实际时长。
- 手机文字每秒更新且相同内容不重写；退到后台停止界面刷新。电平条单独低频刷新，音频采集和传输仍保持原来的 20ms 音频帧节奏。
- Android 使用官方 Material Components 1.13.0 的 Material 3 DayNight 主题、分段按钮、卡片、文本输入框、进度条及对话框。Android 12+ 使用系统动态颜色；较旧系统使用自带的青绿色配色。
- 成功连接后隐藏首次配对输入框；需要连接新电脑时点击“配对新电脑”。顶部时长卡片和底部开始/断开按钮始终易于找到。

## 忘记设备

- 电脑：“设置”→“已配对设备”→“忘记已配对设备”。
- 手机：右上角菜单→“已配对设备”→“忘记设备”。

先断开当前会话，再执行忘记。任意一端忘记记录后，下次需要重新输入配对码；重新配对会生成新的凭据。
当前入口清除该端所有已记住的对应设备。应用卸载、清除应用数据、Windows 用户变更或丢失凭据文件，也会要求重新配对。

设备凭据由手机 Android Keystore 的 AES-GCM 密钥加密保存，电脑由当前用户的 Windows DPAPI 保护；没有长期保存六位配对码。
凭据位于应用私有目录，不随发布包分发。开发测试使用独立的合成凭据。

## 验证范围

- 用户已反馈上一版完成两小时实机测试，传输和断开功能正常；这不等于新增配对机制已通过同样的两小时设备测试。
- 真实 Java 客户端与 .NET 服务端通过 11 次回环握手场景：首次配对、免码重连、双方状态重载、错误/缺少配对码、重放、伪造电脑证明、密文篡改、撤销、重新配对以及设备身份绑定。
- Windows DPAPI 实际加密存储、重载、忘记设备、损坏记录拒绝及显式恢复检查通过；测试不修改真实用户的配对记录。
- Android Robolectric 原生图形渲染和活动测试通过，覆盖每秒文字更新、后台停止刷新/回来恢复、旋转状态恢复、两小时计时及 Material 3 深浅色界面。
- Windows 原有输出路由、实际 WPF 会话/断开、主题及真实蓝牙库释放回归通过；音频输出由合成捕获接收器替代。

本轮没有启动 ADB、连接物理手机或在另一台电脑执行安装。新 APK 在实际 Android Keystore 上的持久化，以及蓝牙免码重连仍需该测试机和手机复测。
首次配对仍应在已由系统配对的蓝牙连接或可信局域网中进行。新握手保护凭据并阻止已配对身份的简单重放/冒充，但没有把 Wi-Fi 音频流改成端到端加密，也不是对首次配对主动中间人攻击的完整 PAKE 防护。
