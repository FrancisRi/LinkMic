# 已配对电脑列表：Windows 0.3.1 / Android 0.2.2

本版把手机“已配对设备”中的数量提示和一键清空，改为可以查看电脑名称并选择遗忘的列表。

## 更新与使用

1. 关闭旧电脑客户端，解压并运行 Windows 0.3.1。
2. 手机覆盖安装 Android 0.2.2；不要卸载或清除应用数据。
3. 使用原来的连接方式连接一次。已经配对的设备继续免码连接，手机会自动补齐电脑名称。
4. 断开后打开手机右上角“已配对设备”，勾选要忘记的电脑，点击“忘记所选”。

电脑名称来自 Windows 当前电脑名，经过身份验证后的加密响应传给手机；不是猜测 IP 对应的名称。电脑更名后，下次成功连接会更新名称。
每项名称下显示简短设备标识，以区分同名电脑。列表可以滚动；未勾选时遗忘按钮不可用，关闭列表不会删除设备。

旧版本没有保存名称，因此刚升级且尚未重新连接时会显示“未命名电脑（连接后更新）”及设备标识。
名称缺失不影响旧凭据，不必重新配对。现有 Windows 0.3.0 必须更新到 0.3.1 才能提供名称，Android 0.2.2 需要新版电脑端；
Windows 0.3.1 继续支持 Android 0.1.0、0.2.0 和 0.2.1 的原握手。

## 遗忘行为

- 仅删除勾选设备身份的记录。名称相同不会导致多删，未选电脑的名称、凭据以及手机自身身份保持不变。
- 删除一台后，其他电脑仍可免码连接；删除全部后，首页重新显示首次配对框。
- 手机忘记一台电脑后，下次连接该电脑需要 PIN，重新配对会轮换该电脑对应的凭据。
- 文件保存失败时保留原记录并允许重试，正常操作不会退化为全部清空。
- 连接期间不能管理设备，管理和保存期间也不能启动新连接。
- 只有配对记录损坏/无法解密时，才显示明确标注的“重置全部配对记录”恢复入口。

## 数据与协议

手机保留原 Android Keystore 密钥别名、应用私有目录和 AES-GCM 文件封装。
旧 `computers[id] = tokenBase64` 记录继续读取；
成功连接后该项升级为 `{token: tokenBase64, name: computerName}`，不更换已有免码凭据。
列表只取得身份和显示名称，不把凭据传给界面。

新手机发送 `LMIC/3`，成功响应的加密明文增加第四项 UTF-8 名称的 Base64。
旧 `LMIC/2` 仍得到严格三项成功响应，保持旧 Android 客户端兼容；音频帧格式和传输服务不变。
认证、凭据保护和首次配对的安全边界见 `PROTOCOL.md`。

## 验证

- Java / .NET 真实回环握手：中文名称传递、重启后免码重连时更新名称，原有 11 个认证场景通过。
- 旧 v2 首次配对与免码重连均验证成功，响应仍为原三项格式。
- 安卓记录层验证旧记录补名、状态重载、同名多设备选择删除、空选择不写入、失败时完整保留凭据。
- Material 对话框验证设备名称、单台/多台/空列表、勾选计数、取消勾选/关闭和选中身份传递，并生成原生界面截图。
- 继续运行之前的计时、模式切换、小屏及深浅色回归，以及 Windows 输出/会话断开/DPAPI/主题回归。

记录层测试用内存存储替代 Android Keystore 文件，使用实际生产迁移和删除逻辑；不能替代物理手机的加密文件和蓝牙测试。
本轮未启动 ADB、安装驱动或操作测试手机。升级后请在原手机确认列表名称和选中遗忘行为。
